# Данные и хранение

Логическая модель данных и правила сохранения. Конкретный формат файлов и классы — предмет следующей итерации.

## 1. Модель данных

Типы указаны в нотации C#. Знак `?` означает, что значение может отсутствовать (`null`).

### Game — игра

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | `Guid` | Уникальный идентификатор |
| `createdAt` | `DateTimeOffset` | Дата и время создания |
| `finishedAt` | `DateTimeOffset?` | Дата и время завершения; `null`, пока игра идёт |
| `finishedEarly` | `bool` | Игра завершена досрочно, до закрытия последней раздачи |
| `players` | `List<GamePlayer>` | Игроки в порядке рассадки, 3–6 |
| `firstDealerIndex` | `int` | Индекс первого раздающего в `players`, от 0 |
| `rounds` | `List<Round>` | Все раздачи игры, создаются при старте |

### GamePlayer — игрок в игре

| Поле | Тип | Описание |
|------|-----|----------|
| `name` | `string` | Имя на момент создания игры (копия), 1–20 символов |
| `playerId` | `Guid` | Ссылка на постоянного игрока; может указывать на удалённого |

### Round — раздача

| Поле | Тип | Описание |
|------|-----|----------|
| `number` | `int` | Номер, с 1 |
| `cards` | `int` | K, от 1 до M |
| `stage` | `RoundStage` | Этап игры |
| `dealerIndex` | `int` | Индекс раздающего в `players`, от 0 |
| `entries` | `List<PlayerRound>` | По одной записи на игрока, в том же порядке, что `players` |
| `closed` | `bool` | Раздача закрыта |

`number`, `cards`, `stage`, `dealerIndex` вычисляются при создании игры и не меняются.

### RoundStage — этап игры

Перечисление (`enum`).

| Значение | Этап |
|----------|------|
| `Ascent` | Подъём |
| `Plateau` | Первое плато |
| `Descent` | Спуск |
| `FinalPlateau` | Финальное плато |

### PlayerRound — запись игрока в раздаче

| Поле | Тип | Описание |
|------|-----|----------|
| `bid` | `int?` | Заказ, `0…K`; `null`, пока не введён |
| `tricks` | `int?` | Взятки, `0…K`; `null`, пока не введены |
| `dark` | `bool` | Играет в тёмную. В финальном плато всегда `true` |

### Вычисляемые значения

Не хранятся, а считаются из введённых данных при каждом изменении:

| Значение | Тип |
|----------|-----|
| Очки игрока за раздачу | `int` |
| Накопленный счёт после каждой раздачи | `int` |
| Место игрока | `int` |
| Активная раздача (первая незакрытая) | `Round?` |
| Порядок заказов | `List<int>` — индексы игроков |
| Запрещённый заказ раздающего | `int?` |
| Состояние игры | `GameStatus`: `InProgress`, `Finished`, `FinishedEarly` |
| Статистика постоянных игроков | см. [screens.md](screens.md#статистика) |

Так правка старой раздачи не может оставить итоги рассогласованными.

Игра завершена, если закрыта её последняя раздача или стоит признак `finishedEarly`. При возобновлении досрочно завершённой игры `finishedEarly` и `finishedAt` сбрасываются. Значения незакрытой раздачи в досрочно завершённой игре хранятся, но в счёт и статистику не входят.

### Player — постоянный игрок

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | `Guid` | Уникальный идентификатор |
| `name` | `string` | Имя, 1–20 символов, уникально без учёта регистра |

Статистика игрока собирается по завершённым играм, где `GamePlayer.playerId` равен его `id`. Связь идёт по идентификатору, а не по имени, поэтому переименование статистику не теряет. Статистика считается либо по всем завершённым играм, либо отдельно по играм на 3, 4, 5 и 6 игроков. Показатели перечислены в [screens.md](screens.md#статистика).

### Settings — настройки приложения

| Поле | Тип | Описание |
|------|-----|----------|
| `tableScale` | `int` | Масштаб таблицы в процентах, 75–200 с шагом 25 |
| `statsPlayerCount` | `int?` | Выбранная разбивка статистики: 3, 4, 5 или 6 игроков; `null` — все игры |
| `window` | `WindowBounds?` | Размер и положение окна; `null` до первого запуска |

### WindowBounds — размер и положение окна

| Поле | Тип | Описание |
|------|-----|----------|
| `x` | `int` | Левый край окна, в пикселях экрана |
| `y` | `int` | Верхний край окна |
| `width` | `int` | Ширина, не меньше 1024 |
| `height` | `int` | Высота, не меньше 640 |
| `maximized` | `bool` | Окно развёрнуто на весь экран |

## 2. Построение раздач

При создании игры для N игроков, `M = floor(36 / N)`:

1. Подъём: K = 1, 2, …, M−1.
2. Первое плато: K = M, N раз.
3. Спуск: K = M−1, …, 2, 1.
4. Финальное плато: K = M, N раз, `dark = true` у всех.

Раздающий раздачи с номером `r`: `(firstDealerIndex + r − 1) mod N`. Следующий игрок в списке сидит слева от предыдущего, поэтому «игрок слева от раздающего» — это `(dealerIndex + 1) mod N`.

## 3. Автосохранение

- Игра сохраняется после **каждого принятого изменения**: ввод значения, отметка «в тёмную», закрытие раздачи, применённая правка, досрочное завершение и возобновление, отмена и повтор.
- Кнопки «Сохранить» нет.
- Незавершённый ввод в ячейке и неприменённая правка строки не сохраняются.
- Сохранение не должно терять данные при сбое: запись идёт во временный файл с последующей заменой.
- Если сохранить не удалось, приложение показывает заметное предупреждение и продолжает работать; попытка повторяется при следующем изменении.

## 4. История игр

- Хранятся все игры — и идущие, и завершённые, без ограничения числа.
- Игра исчезает из списка только при явном удалении пользователем.
- Список постоянных игроков хранится отдельно от игр.

## 5. Место хранения

Данные лежат в личной папке данных приложения, которую выдаёт платформа; на Windows это папка в профиле пользователя. Общий код не знает конкретного пути — так хранение без изменений заработает на Android и iOS.

Состав: файл на каждую игру, файл списка игроков, файл настроек. Формат — текстовый (JSON), чтобы файлы можно было скопировать на другой компьютер.

## 6. Экспорт

Экспорт (CSV, PNG) — это выгрузка для просмотра и печати. Импорта нет: экспортированный файл нельзя загрузить обратно в приложение. Форматы описаны в [score-table.md](score-table.md#11-экспорт).

Выбор места сохранения файла — платформенная операция: на Windows это стандартный диалог «Сохранить как».
