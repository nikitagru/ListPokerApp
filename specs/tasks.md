# Задачи реализации

Полный список работ по созданию приложения по плану из [architecture.md §10](architecture.md#10-план-реализации). Файл — единственный источник правды о прогрессе: по нему новая сессия понимает, что уже сделано и с чего продолжать.

## Как работать с этим файлом

**Начало сессии**

1. Прочитать раздел [Текущее состояние](#текущее-состояние) и [Журнал сессий](#журнал-сессий).
2. Найти первую подсекцию, где есть невыполненные задачи `- [ ]`.
3. Прочитать документы из строки «Читать перед началом» этой подсекции — только их, остальное по необходимости.
4. Посмотреть `git log --oneline -10` и убедиться, что рабочая копия чистая.

Пример запроса для новой сессии: *«Прочитай specs/tasks.md и продолжи с первой невыполненной подсекции»*.

**Во время работы**

- Отмечать задачу `- [x]` сразу после выполнения, а не в конце сессии.
- Если по ходу принято решение, которого нет в спецификации, — записать его в [Решения при реализации](#решения-при-реализации). Если решение меняет поведение приложения — ещё и в [open-questions.md](open-questions.md).
- Если задача оказалась ненужной — не удалять, а отметить `- [x] ~~задача~~ — не нужна, потому что …`.

**Конец подсекции (точка остановки)**

Каждая подсекция с номером вида `N.M` — законченный кусок работы, после которого сессию можно прервать:

1. `dotnet build` без ошибок и предупреждений, `dotnet test` — всё зелёное.
2. Все задачи и критерии готовности подсекции отмечены.
3. Обновлены [Текущее состояние](#текущее-состояние) и строка в [Журнале сессий](#журнал-сессий).
4. Коммит с сообщением вида `Секция 2.2: правила игры (RoundPlanner, Scoring, BidRules, Placement)`.

### 2.2. Правила игры

Читать перед началом: [gamerules.md](gamerules.md) целиком, [architecture.md §4.2](architecture.md#42-rules--правила-игры), [score-table.md §4.1](score-table.md#41-заказы).

`RoundPlanner`:

- [ ] `MaxCards(n)` = `36 / n`; исключение для `n` вне 3–6.
- [ ] `RoundCount(n)` = `2·(M−1) + 2·n`.
- [ ] `BuildRounds(n, firstDealer)`: подъём 1…M−1, плато M ×N, спуск M−1…1, финал M ×N; номер с 1; раздающий `(firstDealer + number − 1) mod n`; в финале у всех `Dark = true`, остальные записи пустые.
- [ ] `GameFactory.Create(players, firstDealerIndex, TimeProvider)` — новая игра с `Guid.NewGuid()`, `CreatedAt`, построенными раздачами.
- [ ] Тесты: число раздач 28/24/22/22 для N = 3…6; последовательность K для каждого N; раздающий идёт по кругу; финал «тёмный»; N = 5 → M = 7.

`Scoring`:

- [ ] `Score(bid, tricks, dark)` по таблице из [gamerules.md §6](gamerules.md#6-подсчёт-очков).
- [ ] `Outcome(bid, tricks)` → `Exact` / `Over` / `Under` (выполненный пас — `Exact`).
- [ ] `Explain(bid, tricks, dark)` → текст расшифровки: «заказ 3, взято 3, в тёмную: 10 × 3 × 2 = +60»; для паса, перебора, недобора — свои формулировки. Знак минуса — `−` (U+2212), как в спецификации; записать, где форматируются числа со знаком (общий `ScoreFormat.Signed(int)`).
- [ ] Тесты: все 8 примеров из gamerules; тёмный пас +10; тёмный пас с перебором (0, 2, dark → +8); штраф в тёмную; перебор при заказе 0.

`BidRules`:

- [ ] `BidOrder(round, n)` — сначала «тёмные» по кругу от игрока слева от раздающего, затем остальные по кругу, раздающий всегда последний (в том числе в финале, где все «тёмные»).
- [ ] `TrickOrder(round, n)` — по кругу от игрока слева от раздающего, раздающий последний.
- [ ] `ForbiddenDealerBid(round)` — `K − Σ заказов остальных`, если все остальные заказы введены и значение в `0…K`; иначе `null`.
- [ ] `CanToggleDark(round, player)` → результат с причиной отказа: раздающий вне финала; финальное плато (отметка заблокирована); в раздаче уже введены взятки.
- [ ] Тесты: порядок без «тёмных», с одним и несколькими «тёмными», «тёмный» сразу слева и справа от раздающего; финал; запрещённый 0 (пас раздающего при сумме остальных = K); сумма остальных > K → запрета нет.

`Placement`:

## Секция 3. Сессия ввода

Цель: `GameSession` полностью реализует поведение таблицы из [score-table.md §4, §6–9](score-table.md#4-ход-раздачи) без интерфейса.

### 3.1. Ввод, закрытие раздачи, отмена и повтор

Читать перед началом: [architecture.md §4.4](architecture.md#44-session--ввод-в-таблицу), [score-table.md §4, §6, §8](score-table.md#6-проверки), [open-questions.md «Согласованные правила»](open-questions.md#согласованные-правила-поведения).

- [ ] `InputResult` — `Accepted` / `Rejected(string message, ImmutableArray<CellRef> culprits)`.
- [ ] `UndoHistory` — два стека снимков `Game`, глубина 500 (старейшие отбрасываются), новое действие очищает стек повтора.
- [ ] `GameChangedEventArgs` — прежний и новый `Game`/`Summary`, `IsCommitted`, `StatusChanged`.
- [ ] `GameSession(Game game, TimeProvider time)`: `Game`, `Summary`, `CanUndo`, `CanRedo`, событие `Changed`.
- [ ] `SetBid(round, player, value)`:
  - [ ] только активная раздача (или строка на правке — в 3.2), иначе отказ;
  - [ ] `0…K`;
  - [ ] раздающий — только после заказов всех остальных, и не запрещённое число («Нельзя заказать 1» / «Пас запрещён»);
  - [ ] заказ остальных — в любом порядке (порядок — подсказка);
  - [ ] `null` — очистить.
- [ ] `SetTricks(round, player, value)`:
  - [ ] только когда введены все заказы и `Σ заказов ≠ K`;
  - [ ] `0…K`;
  - [ ] если после ввода все взятки введены и `Σ = K` — тем же действием `Closed = true`; если это последняя раздача — `FinishedAt = now`, `StatusChanged = true`;
  - [ ] если все взятки введены, но `Σ ≠ K` — значение принимается, раздача не закрывается, ошибка строки из `Summary`.
- [ ] `ToggleDark(round, player)` — через `BidRules.CanToggleDark`, отказ с текстом причины.
- [ ] Решить и записать (в [Решения при реализации](#решения-при-реализации) и [open-questions.md](open-questions.md)): что происходит при очистке или изменении заказа, когда взятки уже частично введены (предложение: разрешено; если `Σ заказов` стала равна K — ошибка строки, ввод взяток блокируется до исправления, введённые взятки сохраняются).
- [ ] `Undo()` / `Redo()` — восстанавливают снимок, пересчитывают `Summary`, выпускают `Changed` с `IsCommitted = true`.
- [ ] Каждое принятое действие кладёт прежний `Game` в историю и выпускает `Changed`; отклонённое — ничего не меняет.
- [ ] Тесты (сценарные):
  - [ ] полная партия на 3 игрока (28 раздач) и на 6 игроков через API сессии, итоги совпадают с `GameCalculator`;
  - [ ] запрещённый заказ и запрет паса раздающего;
  - [ ] заказ раздающего раньше остальных — отказ; заказ остальных вне очереди — принят;
  - [ ] «в тёмную»: раздающему вне финала — отказ; в финале — отказ снятия; после ввода взяток — отказ;
  - [ ] ошибка `Σ заказов = K` после исправления заказа не раздающего;
  - [ ] взятки до всех заказов — отказ; `Σ взяток ≠ K` — раздача не закрыта;
  - [ ] закрытие раздачи и отмена закрытия одним `Undo` (раздача снова активна, последняя взятка очищена);
  - [ ] undo/redo с обрывом цепочки повтора; ограничение глубины 500;
  - [ ] завершение игры последней раздачей: `StatusChanged`, `FinishedAt`; отмена — игра снова идёт.

### 3.2. Правка закрытой раздачи, досрочное завершение

Читать перед началом: [architecture.md §4.4 («Правка»)](architecture.md#44-session--ввод-в-таблицу), [score-table.md §7, §9](score-table.md#7-правка-закрытой-раздачи).

- [ ] `RowEdit` — индекс строки и черновик `Round`; свойство `GameSession.Edit`.
- [ ] `BeginEdit(round)` — только закрытая раздача, только если нет другой правки; в том числе в завершённой игре.
- [ ] `SetBid`/`SetTricks`/`ToggleDark` для строки на правке меняют черновик, не трогают `Game` и историю, `Changed` с `IsCommitted = false`; проверки диапазона и «в тёмную» те же, порядок ввода не навязывается (заказ раздающего можно менять в любой момент).
- [ ] `Summary` во время правки считается по игре с подставленным черновиком (чтобы таблица показывала пересчёт и ошибки строки), но сохраняется только `Game` без черновика — продумать и записать, как `TableStateBuilder` получит оба.
- [ ] `ApplyEdit()` — черновик целиком: `Σ заказов ≠ K`, все взятки введены, `Σ взяток = K`; иначе отказ с ячейками-виновниками. При успехе — одно действие в истории.
- [ ] `CancelEdit()` — черновик отбрасывается.
- [ ] Пока есть правка: ввод в активную раздачу, `BeginEdit` другой строки, `Undo`/`Redo`, `FinishEarly` — отказ (`CanUndo`/`CanRedo` = `false`).
- [ ] `FinishEarly()` — доступно, если закрыта хотя бы одна раздача, нет правки и игра идёт; ставит `FinishedEarly = true`, `FinishedAt = now`; `StatusChanged`.
- [ ] `Resume()` — только для досрочно завершённой; сбрасывает `FinishedEarly` и `FinishedAt`.
- [ ] Свойства-признаки для интерфейса: `CanFinishEarly`, `CanResume`, `CanBeginEdit(round)`.
- [ ] Тесты: правка с применением пересчитывает последующие счета; правка с отменой; некорректная правка не применяется; правка в завершённой игре меняет победителя; блокировки во время правки; досрочное завершение без закрытых раздач — отказ; завершение и возобновление, их undo/redo; значения незакрытой раздачи сохраняются при досрочном завершении и возобновлении.

### 3.3. Маршрут фокуса и ввод числа

Читать перед началом: [architecture.md §4.5](architecture.md#45-session--маршрут-фокуса-и-ввод-числа), [score-table.md §4.1–4.2, §5](score-table.md#5-ввод-с-клавиатуры-и-мышью).

`InputRoute`:

- [ ] `Next(game, current)` / `Previous(game, current)` для `Enter`/`Tab`/`Shift+Tab`: незаполненные заказы в порядке `BidOrder`, затем незаполненные взятки в порядке `TrickOrder`; после закрытия раздачи — первая ячейка «З» следующей раздачи по порядку заказов.
- [ ] `Initial(game)` — куда ставить фокус при открытии игры.
- [ ] `QueueNumber(round, player)` — номер в очереди для подсказки в пустых «З» (пересчитывается при смене «тёмных»).
- [ ] `SuggestedTricks(round)` — если не заполнена ровно одна «В»: игрок и остаток `K − Σ` (если остаток в `0…K`). Значение не попадает в `Game` без подтверждения.
- [ ] `Move(game, current, direction)` — стрелки по ячейкам `З`/`В` (решить и записать: ходят ли стрелки только по редактируемым ячейкам активной строки/правки или по всей таблице).
- [ ] Маршрут для строки на правке — по ячейкам этой строки.

`NumberEntry`:

- [ ] Буфер набора: `Digit(d, k)` → `Commit(value)` / `Wait` / `Reject`; `Enter` → `Commit` текущего буфера; `Backspace` в буфере; `Reset` по `Esc`.
- [ ] При K ≤ 9 любая цифра → `Commit`; при K = 10–12 цифра `1` → `Wait`, вторая цифра → `Commit(1d)`, если ≤ K, иначе `Reject`; `0` и `2–9` → сразу `Commit`.

Тесты:

- [ ] Порядок фокуса с «тёмными» и без, переход от заказов к взяткам, переход на следующую раздачу.
- [ ] Номера очереди после постановки и снятия «тёмной».
- [ ] Подстановка остатка; остаток вне диапазона — не подставляется.
- [ ] Автоподтверждение при K = 9 и K = 12, `1` + `Enter` = 1, `1` + `3` при K = 12 → отказ.

Критерии готовности секции 3:

- [ ] Все сценарии из [architecture.md §7](architecture.md#7-тестирование) для `GameSession`, `InputRoute`, `NumberEntry` покрыты.

Показывается при закрытии последней раздачи и при досрочном завершении (но не при повторном открытии завершённой игры).
- [ ] В завершённой игре блоки победителей выделены, активной раздачи нет, правка доступна.

## Секция 7. Игроки и статистика

### 7.1. Статистика (Core)

Читать перед началом: [architecture.md §4.7](architecture.md#47-statistics), [screens.md §4](screens.md#4-игроки), [open-questions.md п. 13–18](open-questions.md#согласованные-правила-поведения).

- [ ] `PlayerStats`: игрок, игр, побед, % побед, точность заказов, число добровольных «тёмных», среднее место, средний счёт, лучший и худший счёт (последние четыре — `null` в режиме «Все» и у игроков без игр).

- [ ] Тесты: ничьи, досрочные игры, разбивка по числу игроков, удалённый игрок, переименованный игрок (статистика сохраняется), идущие игры не учитываются, игрок без игр.
